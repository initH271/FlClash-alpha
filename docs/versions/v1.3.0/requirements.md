# 服务检测默认选择与自动调度

文档 v1.3.0 是本轮开发里程碑，不等于 APK 版本。此前 UI 优化已随软件 0.8.98 / 2026094010 发布。

## 需求

- 原有 7 个默认服务之外，将现有开发、交易／支付和社交服务加入默认选择，总计 30 项；勾选项保存到配置中，保留显式空选择。
- 增加四种独立可控的自动方式：连接后、节点／配置切换后、打开面板缺失／过期时、定时检测。手动开始与取消继续可用。
- 默认开启前三种，定时默认关闭，检测间隔 15 分钟、结果有效期 10 分钟，允许用户修改。
- 自动检测仅在应用完成初始化、Core 已连接、代理处于运行状态且前台时执行；被排除的网络暂停代理时不自动探测。
- 路由应用完成后防抖 3 秒，快速变更只检测最新状态；实际自动分组节点变化也应刷新，普通列表更新不重复检测。
- 手动和自动共用一个串行调度器；取消后的旧请求、错误和已完成批次的迟到回调不覆盖当前结果。后台暂停自动检测，恢复时补上已过期的定时任务。
- 测试门槛和原有 Core 生命周期职责不变，不把调度器变成第二个启停控制器。

## 验收

设置序列化、旧配置兼容、独立开关、选中项保存、防抖、并发去重、路由失败、缓存有效期、后台暂停／恢复、关闭和销毁必须通过行为测试。原有应用管理器顺序与 Core 失败切换回归须原样通过。

UI 走查覆盖明暗、窄屏、1.4/2.8 字体与中英俄日；Android 无窗口验收使用生产组件和受控响应。完整真实代理与正式发布 APK 的验收边界另行说明。

## 增量更新说明与自动检查

- 最新发布说明必须来自上一正式 alpha 发布源码提交到本版源码提交的 Git 范围，只展示本版的用户可见增量；不累计历史功能或验收日志，不生成完整历史功能清单。生成器修改通过 CNB 需求 #173 的正式流程推进。
- 自动检查默认开启：初始化完成后检查，前台每 6 小时检查，返回前台时补上已到期的任务；后台暂停，手动检查不受自动间隔限制。
- 自动检查串行执行；同一构建本次应用运行只自动提醒一次。后台到达的结果延迟到前台提示，关闭开关／销毁后忽略迟到结果，开关再次开启时检查最新状态。
- 更新说明默认最多显示六行，长说明支持展开／收起；短说明不增加折叠按钮。
- 使用结构化更新说明时显示本版分组及条目；兼容旧说明，过滤 HTML 注释中的重复 JSON 和内部元数据。
- 原发布信息仍传给下载和安装校验；不修改下载、签名验证、权限与用户确认安装流程。
