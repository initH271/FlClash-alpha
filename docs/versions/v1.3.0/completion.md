## 实现

- `ServiceCheckSettings` 与网络设置一同保存，包含四个开关、间隔、有效期及 30 项默认服务；未知服务名忽略、重复项去重、显式空列表保留，时间范围限制为 1–1440 分钟。
- 共享 `ServiceCheckController` 承接手动及自动请求，维护缓存、请求代次、路由快照、待执行请求和定时器。已有探测器仍使用最多 8 项并发及单平台 8 秒超时。
- Core／运行状态、初始化、排除网络暂停、配置 ID、选中映射和实际分组节点变化驱动失效；配置应用／节点切换／监听启动操作通过只读忙碌及完成信号让检测等待，不修改原有 Core 操作。
- 管理器位于 CoreManager 内部，原应用外层管理器嵌套约定保持不变。前后台观察仅影响检测，不接管 Core 或 Android ServiceState。
- 检测面板右侧设置按钮打开独立设置页；四语言文案及代码生成已完成，现有统一圆角与分组列表样式沿用。

## 已解决的验证问题

- 面板销毁时同步通知 provider 会触发 Flutter 生命周期断言：网络取消和请求代次立即生效，界面状态在微任务中通知。
- 新增无条件节点监听会在初始化前触发数据库依赖，导致整文件 Core 回归与单独运行出现差异：改为初始化完成后订阅节点选择。原有 Core 失败切换测试未改并重新通过。
- 纯 provider 测试须像真实管理器一样持有监听，否则派生 provider 会被暂停；测试持有活动订阅、明确派发异步通知，不放宽 3 秒防抖和过期断言。
