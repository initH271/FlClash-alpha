# Telegram 风格 UI 改造需求

用户要求依据最新 Telegram Android 源码学习先进交互与 UI 风格，尤其悬浮 tab 和近似玻璃效果，迁移改造 FlClash 现有 UI，并进行视觉走查、保存关键截图。

源码基线：Telegram `f2908b14133bbffbf7ab04f641ecb5bfaf533242`，公开 HEAD 版本12.10.6；不等同于已核验的商店 APK。实现继续使用现有 Flutter 3.47.1/Material UI，保留当前主题色和业务导航。

## 验收标准

1. 手机底导航采用居中悬浮胶囊、清晰图标与标签、主题适应的半透明/磨砂或液态背景；列表内容实际经过其后，并预留安全区与末行滚动空间。
2. 支持点击、长按拖动预览和释放选择、取消恢复、键盘/语义导航；快速反复操作与路由更新不产生迟到切页或丢失现有页面状态。
3. 实现依据数学结构独立编写的背景采样折射 shader，并正确处理尺寸、像素单位与 GLES 方向。Impeller 真实路径与 Skia/低效果降级分别标注；不得把普通 blur 截图宣称为已验证的折射。
4. 选中态与动画依据研究中的淡强调色胶囊、320ms减速/弹簧吸附和轻按压变化；系统减少动画时取消运动效果，标签、大字体和主题对比仍可读。
5. 桌面导航与公共 UI chrome 做协调适配，业务设置、订阅、核心生命周期与固定签名不改变；不引入 Telegram 账号、素材或服务器能力。
6. 真实组件走查覆盖320/390手机、宽桌面、明暗、大字体、底部安全区、键盘、弹层、滚动内容、快速切页、长按取消、低效果模式；保存关键截图与渲染器证据。
7. 与变更有关的测试、静态分析、构建和最小性能证据通过；既有测试不为绿色改写。若已有测试依赖具体旧布局，保留语义/平台/状态兼容性并在实现中解决。
8. 完成后按项目正式需求流程提交、审查及发布准备，报告源码、CI、签名/双渠道产物和视觉验收的独立结果。

## 不做什么

不复制 Telegram 品牌素材或整段受许可代码，不改代理节点与本机全局代理，不改核心运行状态所有权，不改控制器/保护规则，不声称模拟后端等于真实网络验收。手机全应用或真实设备验收受首次声明和可用设备限制时如实记录。
