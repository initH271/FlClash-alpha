# v1.4.0 完成与验证

状态：本地实现与验收完成；用户已要求发版，正式 CI、审查、合并和发布正在推进。

## 实现

- Core 历史日志按记录 UTC 时间保留，默认 14 天；5 MiB 分片，生产模式取消 20 片容量淘汰。
- 启动、每分钟清理、修改周期与导出时清理；混合分片保留未过期记录，原子改写并恢复活动写入。
- 首次初始化直接传入保存期限，旧配置缺失字段默认 14 天；运行期 RPC、重连与串行最新意图同步。
- 1/7/14/30 天预设及自定义 1–36500 整数天，持久化；4 种语言资源与模型通过生成器更新。
- 旧 RPC 失败后仍继续处理更新的保存周期；自定义输入错误提示允许换行，已通过视觉复查。
- 本期只改变 Core 历史日志，Flutter APP 独立归档保持原策略。

## Android 与日期清理验收

- 独立 headless API34 ARM64 AVD `flclash_logretention_20261006` / emulator-5698。没有操作其他模拟器、手机或 Mac 代理配置。
- 旧配置默认 14 天；1/7/30 天选择保存、自定义 21 天及重启保存、非法 0 输入及取消不改变设置均通过。
- 保存 30 天后重启：31 天记录删除，20/15/13/0 天记录保留；切回 14 天：删除 20/15 天记录并保留混合片的 13/0 天记录。
- 在线注入 22/0 天混合片，21 天设置下周期清理删除 22 天记录，保留 0 天记录和不匹配分片名的无关文件。
- 导出前确认存在过期记录，Core 导出及 Android 保存的合并 ZIP 均不含该过期记录，包含未过期记录。
- 中文设置/选择器、自定义错误提示及英文换行提示截图均复查；最终 UI 修复 APK 的 100 次代理转发 smoke 零错误。

## 同负载性能实测

- 基线：正式构建 2026094012 的本地重签副本，378 个非签名归档项一致；最终测量 APK SHA256 `fcde1674737adb45bc6a58eda7558b95018813430a782201db0788e918512380`。
- 冻结脚本、配置和 AVD；每条件三轮，50 RPS、8 工作者、1 KiB 响应、新 TCP、15 秒采样。App 在后台，实时日志订阅关/开分别测；不测前台日志页渲染。
- 基线及最终测量各 9000 请求、零响应校验错误、零历史队列丢弃，驱动退出码 0。
- 首批修改后 c2fc3f APK 共 9000 请求中 1 次 AssertionError（debug/实时关第 3 轮第 532 请求），驱动退出码 1；完整保留，无样本剔除。最终重测未复现，原因未知，原脚本没有捕获具体 HTTP 状态或长度。

| 条件 | CPU 中位数基线 → 修改后（单核 100%） | P95 中位数基线 → 修改后（ms） |
|---|---|---|
| INFO / 实时关 | 9.48% → 9.66% | 7.65 → 7.45 |
| DEBUG / 实时关 | 9.80% → 9.72% | 9.15 → 6.99 |
| INFO / 实时开 | 9.36% → 9.83% | 8.31 → 7.77 |

CPU 波动范围重叠，没有证明降低 CPU。最终版本 DEBUG 对比 INFO 的 CPU 中位数差约 0.06/0.16 个百分点，仅适用于这组负载。PSS 中位数增加 7.5%–13.6%；未做 Go/Flutter/缓存内存归因，历史目录随测试批次增长，不推断泄漏或内存改善。

## 范围与证据

- 流量确实经过 Go HTTP 代理，经 ADB forward/reverse 回环连接本机源站；AVD 外部网络和 VPN/TUN 关闭。模拟器相对值不能推广为真机功耗、Internet/TUN 或高负载饱和结论；未测多 GiB 历史目录启动扫描。
- 历史 hook 为容量 1024 的 select/default 非等待入队，后台每秒 Flush；上游 Mihomo logCh 仍有同步发送，因此不能把整个日志链路说成完全不阻塞。
- 原 AVD 控制面挂起及重叠驱动/宿主测试轮次没有作为有效样本；QEMU 挂起根因未定，不归因于 App。
- 原始数据、三批比较、脚本/配置/APK 身份、安装/构建日志、日期 fixture 和截图：`audits/telegram-android-20261006/log-retention/`（工作区证据，不是仓库正式发布资源）。
